# 规则 R-BREACH-01 违约责任与救济

- 规则编码：R-BREACH-01
- 规则分类：违约责任
- 判定方式：semantic（LLM 语义理解；违禁免责表述由 hard_check 做 hard_match 辅助）
- 严重度：高
- 状态：active
- 是否隐性：否

## 审核维度（风险信号 / 合规要件）
1. 违约责任具体化：风险信号——仅"违约方承担相应责任/法律责任"等笼统表述；合规要件——主要违约情形（逾期交付、质量不合格、逾期付款、擅自解约）分别对应可执行救济。
2. 违约金/赔偿可计算：风险信号——无计算方式或"赔偿一切损失"空泛；合规要件——违约金比例/金额或损失赔偿计算口径明确（日费率受阈值校验）。
3. 责任上限合理性：风险信号——供方责任无限放大或单方设极低上限；合规要件——责任范围与上限对等合理（故意/重大过失通常不得限责）。
4. 不公平免责：风险信号——"概不负责""最终解释权归我方"等格式条款（hard_match 已覆盖部分）；合规要件——无不合理免除自身责任、排除对方主要权利的表述。

## 审核提示词（给 LLM）
你是资深企业法务，审查采购合同「违约责任与救济」。仅依据合同原文，判断违约责任是否具体可执行、违约金/赔偿是否可计算、责任上限是否对等、是否存在不公平免责条款。
判定标准：笼统"承担责任"而无具体违约情形与救济、违约金无计算方式、责任上限明显失衡、含不公平免责表述，任一即命中。
输出严格 JSON：`{rule_id, hit, severity, location, quote, problem, suggestion}`。
- `quote` 须为原文可逐字检索摘录。
- 发现"概不负责/最终解释权/概不退还"等违禁表述时注明（代码 hard_match 也会独立命中置顶）。
- 防幻觉，不得编造；无法判定输出 hit=false 且 need_human=true。

## 命中输出模板
- 问题：{责任笼统/违约金不可计算/责任上限失衡/不公平免责的具体问题}
- 定位：{章节} {原文摘录}
- 建议：{按主要违约情形分别约定救济；明确违约金计算口径；对等设置责任上限；删除不公平免责表述}
