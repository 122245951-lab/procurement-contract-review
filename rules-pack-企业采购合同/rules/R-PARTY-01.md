# 规则 R-PARTY-01 主体与签约资格

- 规则编码：R-PARTY-01
- 规则分类：主体资格
- 判定方式：rule_check（LLM 按明确要件核验）
- 严重度：中
- 状态：active
- 是否隐性：否

## 审核维度（风险信号 / 合规要件）
1. 当事人名称：风险信号——甲方/乙方全称缺失、用简称、与落款签章名称不一致；合规要件——双方完整法定名称（与营业执照/公章一致）。
2. 签约资格：风险信号——对方为分公司/项目部/内设部门而无授权；合规要件——具备独立签约主体资格或有合法授权。
3. 资质与履约能力：风险信号——特殊行业（建筑、软件系统集成等）无相应资质描述；合规要件——按标的需要具备相应资质/许可。
4. 联系与送达信息：风险信号——无住所、法定代表人/联系人、联系方式；合规要件——主体信息齐全，便于履约与送达。

## 审核提示词（给 LLM）
你是资深企业法务，正在审查一份采购合同的「主体与签约资格」。请仅依据下方合同原文，逐条核验上述审核维度。
判定标准：当事人名称完整且与签章一致、具备签约主体资格或有授权、按标的需要具备相应资质、主体联系信息齐全；任一要件缺失或前后不一致即视为命中。
输出严格 JSON：`{rule_id, hit, severity, location, quote, problem, suggestion}`。
- `location` 为章节/条款号；`quote` 必须是合同原文中可逐字检索到的摘录（不要改写）。
- 若合同原文无相应内容（要件缺失），`quote` 填原文中最接近的开头/落款部分，并在 problem 说明"缺失"。
- 防幻觉：不得编造合同中不存在的主体名称或事实；无法判定时输出 hit=false 且 need_human=true。

## 命中输出模板
- 问题：{主体名称不一致/缺少授权/资质未体现/信息不全的具体问题}
- 定位：{章节} {原文摘录}
- 建议：{补全法定全称、要求提供授权书/资质证明、核对签章一致性等可执行建议}
