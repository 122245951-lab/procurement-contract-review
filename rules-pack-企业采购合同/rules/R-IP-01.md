# 规则 R-IP-01 成果与知识产权归属

- 规则编码：R-IP-01
- 规则分类：知识产权
- 判定方式：semantic（LLM 语义理解）
- 严重度：高
- 状态：active
- 是否隐性：否

## 审核维度（风险信号 / 合规要件）
1. 定制成果归属：风险信号——定制开发的软件/系统/设计/文档成果归属未约定或归供方，委托方仅获有限使用权；合规要件——委托开发成果（含源代码、文档、设计稿）知识产权归委托方或委托方享有永久、不可撤销、可转授权的使用权。
2. 背景知识产权：风险信号——供方背景专利/组件授权范围、期限不明；合规要件——供方背景 IP 授予委托方为使用成果所必需的许可，范围清晰。
3. 第三方侵权保证：风险信号——无侵权担保；合规要件——供方保证成果不侵犯第三方知识产权，侵权时由供方负责处理并赔偿。
4. 开源合规（软件类）：风险信号——使用开源组件未声明，传染性开源（GPL 类）风险；合规要件——声明开源组件清单与许可证，避免传染性许可污染专有成果。

## 审核提示词（给 LLM）
你是资深企业法务/知识产权顾问，审查采购合同（尤其软件与系统开发、服务外包）「成果与知识产权归属」。仅依据合同原文判断上述四维。
判定标准：定制成果/源码/文档归属清晰且委托方权利充分、背景 IP 授权范围明确、有第三方侵权担保、（软件类）开源合规有约定；存在归属缺失、权利受限、无侵权担保即命中。
输出严格 JSON：`{rule_id, hit, severity, location, quote, problem, suggestion}`。
- `quote` 须为原文可逐字检索摘录；要件缺失在 problem 注明"未约定"。
- 若合同标的明显不涉及成果/知识产权（如标准货物买卖），可 hit=false；但软件/开发/服务类合同必须重点审查。
- 防幻觉，不得编造；无法判定输出 hit=false 且 need_human=true。

## 命中输出模板
- 问题：{成果归属缺失/委托方权利受限/无侵权担保/开源风险的具体问题}
- 定位：{章节} {原文摘录}
- 建议：{明确定制成果与源码文档归属委托方或授予充分许可；界定背景 IP 授权；加入第三方侵权担保与赔偿；软件类补开源清单}
