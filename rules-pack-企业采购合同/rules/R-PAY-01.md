# 规则 R-PAY-01 价款与支付安排

- 规则编码：R-PAY-01
- 规则分类：价款支付
- 判定方式：rule_check（LLM 按明确要件核验；金额/比例/账期由 hard_check 做 value_check 辅助）
- 严重度：高
- 状态：active
- 是否隐性：否

## 审核维度（风险信号 / 合规要件）
1. 金额与币种：风险信号——无总价/单价、币种不明、大小写不一致；合规要件——金额明确、币种清楚、大小写一致。
2. 付款节点与触发条件：风险信号——仅"验收合格后付款"却无验收标准，或节点模糊；合规要件——付款与可验证的交付/里程碑挂钩，触发条件可执行。
3. 账期：风险信号——账期过长或未约定；合规要件——明确付款期限（账期天数受阈值校验）。
4. 付款方式与账户：风险信号——付款方式、收款账户不明；合规要件——方式（转账/票据）、账户信息明确。
5. 发票约定：风险信号——未约定发票类型/税率/开票时点；合规要件——明确发票（增值税专票等）与付款的先后关系。

## 审核提示词（给 LLM）
你是资深企业法务/财务，审查采购合同「价款与支付安排」。仅依据合同原文核验上述维度。
判定标准：金额币种明确、付款节点与触发条件可执行、账期清晰、付款方式与账户明确、发票约定完整；任一缺失或不可执行即命中。
输出严格 JSON：`{rule_id, hit, severity, location, quote, problem, suggestion}`。
- `quote` 必须为原文可逐字检索的摘录；要件缺失时在 problem 注明"未约定"。
- 涉及账期天数、预付款比例、违约金费率的，交由代码 value_check 验算，你只需指出条款位置与表述问题。
- 防幻觉：不得编造金额或条款；无法判定输出 hit=false 且 need_human=true。

## 命中输出模板
- 问题：{金额/节点/账期/方式/发票中缺失或不可执行的具体问题}
- 定位：{章节} {原文摘录}
- 建议：{明确金额币种与大小写、将付款绑定可验证里程碑、约定账期与账户、补充发票条款等}
