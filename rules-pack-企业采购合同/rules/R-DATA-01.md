# 规则 R-DATA-01 保密与数据安全

- 规则编码：R-DATA-01
- 规则分类：保密数据
- 判定方式：semantic（LLM 语义理解；违禁数据表述由 hard_check 做 hard_match 辅助）
- 严重度：高
- 状态：active
- 是否隐性：否

## 审核维度（风险信号 / 合规要件）
1. 保密义务与期限：风险信号——无保密条款或保密期"永久"过严/过松无约定；合规要件——明确保密信息范围、保密义务、保密期限（可约定合同终止后持续若干年或长期）。
2. 个人信息/数据合规：风险信号——涉及个人信息处理却无合规约定；合规要件——涉及个人信息的，约定处理目的、范围、安全措施、不得擅自留存/外传，符合个人信息保护要求。
3. 泄露响应：风险信号——无数据泄露通知与补救；合规要件——发生泄露及时通知、采取补救、承担责任。
4. 离场数据移交销毁：风险信号——合同结束后数据去向不明；合规要件——终止/解除后按委托方要求移交或销毁数据并出具确认。
5. 审计/监督：风险信号——无合规审计权；合规要件——委托方对数据处理有监督/审计权利（服务外包/数据处理类尤其需要）。

## 审核提示词（给 LLM）
你是资深企业法务/数据合规顾问，审查采购合同「保密与数据安全」。仅依据合同原文判断上述五维。
判定标准：保密范围义务期限明确、涉及个人信息时有合规约定、有泄露响应、有离场移交销毁约定、（数据处理类）有审计权；存在缺失或"可任意使用/披露对方数据"类表述即命中。
输出严格 JSON：`{rule_id, hit, severity, location, quote, problem, suggestion}`。
- `quote` 须为原文可逐字检索摘录；要件缺失在 problem 注明"未约定"。
- 发现"可任意使用/披露"对方数据等违禁表述时注明（hard_match 也会独立命中）。
- 防幻觉，不得编造；无法判定输出 hit=false 且 need_human=true。

## 命中输出模板
- 问题：{保密义务/个人信息合规/泄露响应/离场销毁/审计权中缺失或表述危险的具体问题}
- 定位：{章节} {原文摘录}
- 建议：{补保密范围期限；个人信息处理合规条款；泄露通知补救；终止后移交销毁并确认；数据处理类加审计权}
